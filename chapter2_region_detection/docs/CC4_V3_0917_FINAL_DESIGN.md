# 一、决策范围与官方动作契约

## 1.1 任务与信息边界

[原文]及时消除攻击，同时减少正常运行失败；LLM给多步计划，WM预测未来影响，PPO选择计划，只执行第一步。[P1，第2页]

策略、先验检索、目标解析和动作mask只读取当时已到达的合法Blue观测、自身行动记忆与公开动作规则。真实Red会话、真实失陷标志/起点、未来观测、未来奖励、评测标签不能进入这些输入。

仿真真值仅允许在隔离的训练奖励/监督标签及最终评测通道使用。用隐藏状态构造奖励，不等于允许用它决定动作。五个Blue的局部观测不能未经通信协议直接拼给某一个策略；本版不增加跨域通信模块。

## 1.2 四类动作的解释

0—3是本项目高层编码，不是所有CC4 wrapper通用的底层动作索引。默认duration由官方动作表给出，单位为全局仿真tick，不是秒。[S1]

| ID / 名称 | CC4动作 / 时间 | 官方作用和能力限制 | 写入LLM的规划提醒 |
|---|---|---|---|
| 0 / no_op | Sleep / 1tick | 当前不主动干预；不清除会话、不重置主机。Monitor通常在每步结束自动提供进程/网络相关事件。[S2][S3] | 等待不等于停止全部观测，也不等于执行文件调查；不保证无后续业务损失。 |
| 1 / analyse | Analyse / 2ticks | 调查指定主机，提供恶意软件相关文件等证据；不是清除。执行成功也可能没有新增观测。[S4] | 有助于改变后续判断时再调查；不能作为所有处置的必经前置步骤。成功、发现证据、清除攻击必须区分。 |
| 2 / remove | Remove / 3ticks | 清除用户级红方会话，不能替代Restore清除root级会话；官方例子中success=True仍可能保留root会话。[S5] | 不得称为清除所有恶意活动；重复Remove不保证清除高权限失陷；缺少真实权限标签不等于该动作非法。 |
| 3 / restore | Restore / 5ticks | 主机重镜像，恢复已知良好状态，清除恶意活动和被红方修改的文件；会影响恢复期间可用性。[S1][S6] | 同时说明彻底处置能力与扰动成本，不能只强调最慢；允许立即Restore，但不强制或无依据反复Restore；恢复不代表永久免疫。 |

提示词还必须说明：四步计划是四次顺序完成的响应，不是四个相邻tick各发起一个动作。已启动动作不能取消，当前动作未完成时不创建新的自主决策。[S1]

## 1.3 公共执行接口

所有主方法和消融使用同一目标解析器、合法性规则和底层适配器。目标解析先于候选选择，基于同一决策快照；LLM仅输出动作类别，不另造目标。

“可执行但可能不划算”不能被当成“不合法”。先验低、WM不确定、动作慢、尚未证实感染都不是新增屏蔽理由。若实际wrapper额外要求会话/目标可达等条件，忠实记录该条件，不以高层文档覆盖它。

请求、提交、实际执行、完成、实际根除分别记账。请求Restore映射成Sleep不能算Restore执行，也不能算有效Restore覆盖。执行前状态变化引发拒绝时保存原因，不事后删除样本。

仅Sleep合法时绕过LLM/候选选择；忙碌时继续环境推进和观测记录。强制行为和忙碌tick仍计时间与奖励，不产生虚假的actor探索样本。

## 1.4 八条候选的硬约束

每个合法首动作恰好两条完整序列，长度4，组内去重。四动作都合法时8条；部分合法时2×合法动作数条有效候选，填充至8个存储槽并mask。仅Sleep合法为强制特例，不凑两条。

```text
for a in legal_actions:
    count(valid_plan.first_action == a) == 2
```

一次LLM请求按首动作分组生成。两条计划应在后续动作上有有意义的差异，不要求固定“一条保守、一条激进”。只改理由或评分不算不同序列。

解析顺序：校验JSON/枚举/长度/有限评分 → 按真实首动作归组 → 完整序列去重 → 组内排序保留两条 → 缺失组确定性补齐 → 应用mask → 校验不变量。禁止跨组全局Top-N；不能改一个计划首动作后沿用原评分和理由。

补齐池保持已确认规则，对首动作a按顺序扫描并跳过已存在序列：

```text
(a,0,0,0), (a,1,0,0), (a,2,0,0), (a,3,0,0)
```

source标记llm或deterministic_fallback。备用的raw_prior_score=null、prior_score_present=false；数值输入用本批有效LLM评分均值填补，全部缺失时0.5。此值不是LLM置信度。原始LLM评分使用[0,1]范围校验；本版修正分支直接读取有限score_input，不再施加组内归一化、log(prior)硬屏蔽或额外先验损失。

无效槽位不进入softmax、熵、候选统计、归一化拟合或池化。零/未知先验和高不确定性不允许产生额外-inf屏蔽。候选ID、序列、先验、g/u及mask必须同步。

# 二、同源事件输入与低成本LLM先验

## 2.1 保留的事件记录

[已确认]从一份事件账本生成数值v_t和模板文本c_t；不额外调用LLM总结日志。

```text
v_t = concat(D27_t, target_evidence_t, response_memory_t)
c_t = template(the_same_causal_record)
```

D27原字段含义和次序保持。追加记录包括：公共解析器对应的三个非Sleep动作目标，目标的合法可见元数据，进程/连接/文件证据，证据首次和最近可见时间，新旧证据区别，自身真实响应及结果，缺失与截断标记。

实际目标去重后最多3台，不另造top-3主机。内部历史按episode、agent、稳定可见主机标识保存；目标切换不能串用另一主机的记忆。文本合并相同主机；数值槽按动作类型对齐，保留同目标关系，不按风险排名交换槽位。

近期窗口50个全局tick；每主机最近4次已完成响应；另保留Analyse/Remove/Restore各自最近一次完成时间及结果，超过窗口也保留，但不跨episode。执行中单独标记，不能提前填入未来结果。

首次观测、重复返回、处置后首次观测分开。没有源事件时间时，只说“首次观测到”，不推断真实发生时间；动作后新告警不自动等于动作导致或root失陷。unknown、not_observed、no_new_observation与明确否定分开。未重新返回旧证据不等于它消失；日志裁剪不等于主机恢复。

## 2.2 字段展开规则：不再猜一个D40/D64

[本次收尾]实现时按固定字段注册表自动展开维度，生成`feature_schema.json`。这是环境绑定工作，不再另选模型路线。

注册表必须对每个字段给出：源Blue字段/自身记录、可见时间、实体键、dtype、单位、缺失mask、变换、所在向量slice、是否可预测、是否规则更新。基础D27固定在前27位。

每个动作目标槽的追加字段固定包含以下组：
1. 目标存在/合法mask、可见主机角色与区域、动作间同目标关系。
2. 进程/连接/文件的近期计数、首次/最近可见年龄、新增/重复与缺失标记。
3. 最近4条完成记录的存在mask、动作类别、结果类别、开始/完成年龄、实际持续时间、处置后新证据及其已知性。
4. 三类主动动作各自最近一次完成时间、结果及存在mask，和历史截断标记。
5. 同源证据文本的轻量语义表示；不只给无LLM分支一个“有文件”布尔值。

数值年龄以500tick作固定缩放，计数用log1p，二值/类别不当成连续缺失零值。文本字段采用固定、可复现的128维非训练式token hashing（每个目标槽一组），输入token与模板使用相同证据来源；哈希种子固定，不使用Python进程随机hash。保留原token与碰撞/截断统计，不声称压缩无损或与LLM编码能力相同。未知类别有专门标记。

最终D由该表展开后计算并写入manifest；不得先写一个声称已经审计的维度。实际接口未提供某字段时按unknown处理，不访问控制器补齐。该探测、slice一致性及来源核验须在正式训练前完成，后续全部变体共享同一schema。

文本按字段模板生成，保留实际目标和四条响应事实。单次incident摘要先以2,000个token为上限，优先压缩重复证据，显式标记省略；不能截掉整个目标或关键历史而不记录。自由文本只作证据，转义并隔离，不能执行其中指令。超长案例触发日志与固定截断规则，不在测试时人工改写。

## 2.3 先验库构建

[本次收尾]固定采用离线方案：先20个训练状态检查结构，再累计200个代表状态；匹配报告显示覆盖空白时，从训练数据补到最多400，不默认做更大的库。

200是代表状态数，不是episode数。一个状态一次产生全部合法首动作组。选样来自训练轨迹，兼顾尚未响应、Analyse后、Remove后、Restore后、新旧证据、可见角色和目标关系；先按这些可见条件分层，再按固定seed去重和均衡抽样，不按未来奖励或真实感染标签挑选。

五次正式重复各自从该repeat的基础训练数据产生先验库；同repeat的LLM-RL/LWM-RL复用，避免额外调用。不同repeat重新生成的随机性及重复使用的精确相同请求分别登记。开发库不自动替代全部正式库；相同请求复用仅在输入、模型、提示和生成配置完全一致时允许。

使用用户当前已验证可调用的教师接口，不在本轮随意更换模型。provider、真实API model_id和生成参数由部署配置绑定；不把旧文档里的显示名称当作已验证的官方型号，不存储API key。首20个请求确认JSON能力和具体模型身份后固定，未绑定不得开始付费批量构建。运行阶段零LLM API调用，离线失败最多一次原配置重试；失败结果走确定性补齐并计费/来源记账。

## 2.4 精确匹配＋受约束近邻

先对规范化完整事件记录和协议版本做精确缓存。未命中时仅在关键条件一致的库记录中找最近一个，不合并多个近邻的计划。

关键条件包括：合法动作mask、动作到目标的同一性关系、目标可见角色/区域、最近响应类别及结果、处置后新证据和关键缺失标记。原主机名不作为跨episode身份要求，但实体关系不能变；不跨不同角色强行匹配。关键证据token出现未覆盖的新类别时拒绝近邻复用，不以数量接近代替语义一致。

近邻距离采用三个等权块的有效数值距离：D27动态部分、目标证据、完整四条响应历史。每块先按训练统计缩放，再取有效维度均方距离；三个块等权平均后开根。ID、seed、精确缓存hash不进入距离。关键类别先过滤，不以距离小抵消类别不一致。

距离上限不凭空写相似度0.8。按训练episode分组留出、禁止自身及同episode近邻，得到有效最近距离，取95%分位作为固定初值。一个关键条件组不足5个跨episode参照记录时只允许精确匹配或回退，不借阈值无限放宽。阈值、统计量、词法规则及库在后验训练前冻结；验证/测试不更新。

这项分位规则仅界定训练分布中的近似范围，不证明语义正确；须保存匹配审计和各情形覆盖率。所有检索均可用普通数组距离实现，不引入向量数据库或新的学习网络。

## 2.5 未命中与部分修复

没有合适记录时使用1.4节备用池，所有合法首动作仍两条；本次`enabled_L=false`，修正项严格为零。基础PPO及该变体的WM继续工作，不强制Sleep、不在线补答案、不丢弃episode。这明确替代旧缓存文件的“正式cache miss即拒绝运行”规则。

部分候选来源缺失按score_present标记保留，不冒充LLM置信；全批没有LLM来源时必须关闭整条LLM修正。回退率不能靠降低合法动作数来美化。

近邻只借用动作序列、原始评分和来源信息，不复制来源目标、状态、历史、g/u或V_ref结果。WM必须从当前v_t重新推演。来源理由只作检索审计，不能当作LLM对当前状态的新推理。

记录精确命中、近邻命中、拒绝原因、距离、来源ID、原始/修复覆盖、各动作补齐率、LLM分支启用率、墙钟和token数。库内记录查自身不能用于报告泛化命中率。400仍覆盖差时报告部署限制并停止扩展论证，不声称LLM已充分发挥，也不自动再加几千条。

# 三、世界模型与候选评分

## 3.1 五成员状态—双损失模型

[已确认]5个独立小型概率MLP。每个成员内部共用骨干，输出不确定的下一可观测状态、间隔延迟损失D、业务失败损失F；成员之间独立初始化和episode级bootstrap。不能复制一个模型五次，也不能让五个动力学成员仍只依赖一个未集成总奖励模型。

输入是当前事件向量、当前动作、当时可知的目标及计划时长/剩余episode时间；实际未来完成结果或实际dt不能作为预测前输入。下一状态标签在该响应结束后的下一可决策时刻取值。

已知身份、动作记录和确定的时间推进由规则更新；新证据、结果和无法确定的动态统计由模型学习。不能因计划选择Restore就强制未来成功或零损失。窗口计数只有保留足够年龄信息才可精确更新；否则作为预测量。类别结果使用分类头，连续量用适当数值分布，不把所有字段当无约束实数。

[本次收尾]未来目标不访问真实环境重算。首步目标绑定当前公共解析结果；后续向量中的目标摘要是模型对下一次解析结果的预测，不能假装知道新的真实hostname。确定记忆更新仅用于仍能明确对应的实体；目标身份/对应发生不确定变化时，下一目标的摘要及记忆作为动态预测并带未知标记，不把上一目标历史硬移过去。训练和多步验收必须覆盖目标切换；若此投影未通过，不发布四步rollout已正确的声明。

同一状态、目标、首动作的两条候选，第一步条件预测相同，第二步后才因尾部不同分叉。预测状态不重新调用LLM，不生成假自然语言日志。

## 3.2 奖励与时间保持一致

[原文/既有配置]每tick恢复延迟为受跟踪主机仍处于失陷事件时的事件年龄之和，失败项为所有受跟踪Blue管辖主机的Host Work Fail原始负惩罚的绝对值，而非仅当前响应目标。当前仓库配置lambda_time=1、lambda_failure=1、gamma_tick=0.99；本版保留这组权重，不冒称是论文给出的最佳权重。[C1]

令d_t、f_t≥0为两个既有分量；每个智能体的一次真实响应间隔实际长度dt使用：

```text
D_t = sum(gamma_tick**l * d[t+l], l=0..dt-1)
F_t = sum(gamma_tick**l * f[t+l], l=0..dt-1)
R_t = -lambda_delay*D_t - lambda_failure*F_t
```

真实episode结束、回退和拒绝按实际dt记；完整逐tick原日志保留。对五个agent可分别构造各自间隔的同目标学习样本，但官方团队指标每tick只统计一次，不乘五。

为数值稳定，PPO统一使用`R_train = 1e-3 * R_t`，所有Table2变体及对应V_ref相同；这是整体正比例缩放，不改变两分量相对权重。WM的D/F用各自训练尺度拟合，预测后先还原原单位再合成。V_ref若输出缩放单位，加入计划g前除以1e-3。独立归一化监督损失不等于重新平衡策略奖励。

不能用业务失败“次数”代替官方加权失败“惩罚”；不能把正惩罚量又以正奖励相加；不能只在rollout里更新奖励而PPO仍用旧版。标签文件必须与新间隔折扣匹配。

## 3.3 训练方式与数据

[本次收尾]初版骨干128×128/ReLU、Adam学习率3e-4、batch256、最多50epochs、验证patience5。连续动态头采用对角高斯NLL，二值/类别头使用对应交叉熵；两损失头各自输出非负均值及方差。连续标签仅按训练统计变换，方差数值范围固定；未知项mask，不参与对应损失。按状态块、D头、F头分别取有效元素均值再等权相加，避免一个大块因维度多主导训练。

bootstrap在训练episode层面；WM验证为独立episode，不与PPO采样数据混入训练。优先复用2万步基础训练完整轨迹，若某动作上下文缺失只在训练环境补采并另计预算。没有原始历史、tick分量或字段时不编造补齐旧replay。

按四动作报告状态动态误差、D/F误差、偏差、样本数及不确定性—误差关系，与持久状态、训练均值预测比较。固定身份字段不能稀释动态误差。普通轨迹只能检验实际执行动作，不提供未执行候选的真实反事实regret。

## 3.4 四步回报与参考尾值

按成员m独立递推候选i，累计全局经过时间tau_h，不超过H=4，任务终点提前停止：

```text
G[i,m] = sum(gamma_tick**tau_h * R_hat[i,m,h])
         + use_tail_value * nonterminal
           * gamma_tick**tau_H * V_ref(v_hat_H)
g_i = mean_m G[i,m]
u_i = sqrt(mean_m (G[i,m] - g_i)**2)  # ddof=0
```

R_hat已含间隔内部折扣，外层仅折扣间隔起点，不能重复折扣。V_ref为本repeat、同新输入/奖励的2万步参考PPO critic冻结副本，不与当前在线critic共享可训练对象。真正500tick任务终点尾值为0；训练buffer截断不当作真正终止。

这是“执行短计划后接续参考策略”的近似价值，不是保证实际闭环会兑现尾部处置。不同动作结束时间不同，尾值对应各自剩余时间。跨任务终点的动作必须有实际截短间隔标签；无此能力时禁止按比例编造完整动作损失并通过验收。

固定成员均值递推，不加粒子搜索。连续均值和类别概率/约束投影是近似，不能宣称精确期望。u仅表示五个模型对回报的分歧，不是置信区间，无法覆盖所有共同偏差和单个V_ref误差。原始状态分歧与两分量保留作诊断，不新增一串PPO输入。

## 3.5 数值处理与启用规则

[本次收尾]g/u在训练侧有效候选上分别拟合均值、标准差，按`(x-mean)/max(std,1e-6)`转换并裁剪到[-5,5]。跨动作共用尺度，不按Restore/Analyse各自居中；测试不更新。近常数特征标准化为0并记录，不用放大数值噪声；NaN/Inf为接口错误，不能变成隐式禁用某个动作。

仅提供g_input、u_input两个WM主特征。记录raw值、尾项占比、各动作裁剪率。参考模型或尾值开关改变时重新拟合相应normalizer，不能替换已训练actor的输入含义而假装是重训对照。

尾值默认配置为off，approved option为on。开发分别从同一基础checkpoint完整训练off/on配置；不在测试时切换。WM-RL与LWM-RL使用同一最终开关；仅当两者各自on相对off的8episode验证官方回报均改善，且失败惩罚和未恢复率满足第五章的容忍线时才统一开启，否则统一保持off。对照不增加网络，负结果保留，成本另列。该有限样本筛查不是统计性能保证。

# 四、PPO后验选择与训练日程

## 4.1 已确认的轻量残差评分

```text
z_i = b_theta(v_t,a_i)
      + enabled_L * tanh(f_L(v_t,plan_i,score_input_i,score_present_i))
      + enabled_W * tanh(f_W(v_t,plan_i,g_input_i,u_input_i))
pi_i = masked_softmax(z)_i
```

b一次输出4个动作评分，不看LLM/WM信息；两个修正分支各自对所有候选共享参数，读取完整4步one-hot编码，不以候选编号为价值信息。各分支和独立critic不共享可训练编码器。每个修正范围[-1,1]，最后一层权重/偏置为0，隐藏层正常初始化。

本版不新增学习门控、分层PPO或硬风险惩罚。enabled开关严格清零对应输出；仅把输入置零不等同关闭。初始两个修正为零且每个合法动作两条时，候选概率按首动作求和正好等于基础A4 softmax。关闭修正只恢复当前基础参数的行为；若基础参数已经更新，不保证恢复原参考模型性能，故原始参考checkpoint独立保存。

critic为独立状态MLP，仅用真实环境奖励训练；V_ref是冻结副本。不能把WM想象样本塞进PPO当作真实on-policy轨迹。WM有用与否最终看实测，不以修正分支存在或输出非零作为证明。

## 4.2 采样和更新

训练按候选pi采样i，执行a_i，保存当时完整候选/特征/mask/目标映射/旧log_prob。一个buffer内重复PPO更新时，不重新检索或改变WM及预处理。概率比分子分母都是同一个候选概率，不混用A4边缘概率。

确定性验证/测试：先求`P_A(a)=sum(pi_i:first_action=a)`，选最大动作组，再选组内最大候选。并列按动作ID与规范序列打破，不按可变槽位顺序。此处没有额外分组网络。主要熵为A4边缘熵，候选熵只作诊断。

强制Sleep与忙碌时间不产生actor损失，但相关奖励和下一价值不能丢失。按各agent自己的有序响应间隔构造优势，不能跨agent或episode递推。

[本次收尾]时间一致的优势定义：

```text
delta_n = R_train_n + gamma_tick**dt_n * continuation * V(v_next) - V(v_n)
A_n = delta_n + (gamma_tick*lambda_gae_tick)**dt_n * continuation * A_next
```

lambda_gae_tick=0.95，在本实现中明确按tick衰减；这是semi-Markov适配，不把它与按决策步lambda混用。任务终止continuation=0，批次截断按正确下一状态bootstrap。actor仅对自主选择样本更新；critic可使用真实强制间隔。

## 5.4 四项指标的实现定义

原文给出指标类别；既有任务书对未恢复事件等作了工程细化，本版继续采用，并要求在论文表注明确差异。[P1，第3页][C2]

1. **CC4 official reward（越高越好）**：每episode按全局tick累加环境团队原始官方奖励，每tick一次，再对100episode均值。不使用训练缩放/折扣，不人为除以区域数降低量级。
2. **Operation failure penalty（越低越好）**：全Blue管辖主机Host Work Fail原始负惩罚绝对量按tick累计后取episode平均，不只统计受感染/当前目标主机。失败次数另报，不当作惩罚值。
3. **Recovery precision（越高越好）**：实际提交、执行完成的Remove/Restore，依据开始前目标是否处于active incident计TP/FP；micro TP/(TP+FP)。回退Sleep或未真正执行不入分母，分母为0写NA并报告原因，不能写1。此为处置目标精确率，不等于根除成功率；后者另报。
4. **Recovery time（越低越好）**：对每个事件使用`min(t_recovered, episode_end)-t_compromise`；未恢复计到500tick任务末。对repeat全部事件micro平均。另报completed-only恢复均值和未恢复率。事件为感染从无到有的连续区间，彻底清除后再感染建立新事件；初始已感染在任务观测起点起计，规则写入事件跟踪器。

这是“episode-end受限观察时间”，不是对真实无限期恢复时间的无偏估计，也不是自动满足独立删失假设的生存分析。原稿仅给出完成恢复时间的简式，必须补充截尾统计说明；不能声称与参考硕士论文的均值直接等价。

团队官方奖励是主表口径；各可审计区域可另作诊断，区域聚合权重固定，不将同一团队reward复制成四个区域再平均。也不把5个Blue、4个网络、若干安全区当成同一数量概念。文稿中的“各区域平均”草注须修改为明确的团队/主机统计范围。

## 5.5 checkpoint、尾值开关和预算的冻结规则

检查点20k、30k、40k、50k；扩展时60k、70k、80k，使用同8个验证episode和确定性执行。以验证官方回报最大选checkpoint，精确并列选更早；同checkpoint输出全部指标。选最佳checkpoint不要求完整模型领先。

[本次收尾]“明显退化”诊断线：相对指定对照，失败惩罚增加超过`max(5%,1个原始惩罚单位)`，或未恢复率增加超过3个百分点时标记审查。该线用于开发风险提示及尾值开关，不是屏蔽负结果的发表门槛。不能因为恢复精确率下降就自动忽略官方回报，四项指标一并解释。

尾值on必须使WM-RL、LWM-RL各自验证回报相对off的改善超过`max(对照绝对回报的1%,1个原始奖励单位)`，且均不越上述诊断线；否则统一off。只做这一次小规模A/B，不扫描多个尾值权重或反复挑种子。

预算扩展在开发repeat上决定：若任一Table2变体的30k→40k→50k验证回报连续改善，且50k相对40k改善超过同一1%/1单位阈值，接口正常且失败/未恢复不越线，则所有变体获得80k预算上限；否则50k。不是只给完整方法追加。若全部很差而平坦先排错，不能声称收敛。阈值是先验工程筛查，不是显著性标准。

正式重复前固定库规模、尾值开关、50k/80k协议和所有超参。最终测试后不再挑checkpoint、更新normalizer或扩先验库。需要修改时另立开发版本，并为未来正式结论保留新测试集。保留全部开发负结果与失败原因。
