## 0. 主线与决策管理

### 0.1 保留的研究主线

LLM 基于事件信息生成多步候选计划及先验偏好；集成世界模型进行候选级前瞻评估；PPO 学习计划后验选择；只执行所选计划首动作，在下一次可决策时刻重新规划。[P1]

## 1. STEP-01：官方动作契约与均衡首动作候选生成

### 1.1 目标、结论与范围

本步修复的问题是“LLM 候选接口遗漏关键合法首动作”和“不同首动作拥有的候选数量不一致”。保留 LLM 生成多步计划、WM 评估计划、PPO 选计划首动作的主线。

确定采用：

```text
n_actions = 4
num_candidates_max = 8
plans_per_legal_first_action = 2
plan_horizon = 4
```

本文档用 N 表示候选数量，用 H 表示计划长度；对应最终文稿中候选数 N、计划长度 K。实现中使用具名配置 num_candidates / horizon，禁止复用一个 K 同时表示两个概念。

8条是优先实施配置，不是已经实测优于12条。12条（每组3条）仅保留为未来验证选项，本步不同时更改候选规模、奖励及模型结构。覆盖所有合法首动作不代表各动作必须等概率，更不代表各动作最终使用率必须为25%。

### 1.2 官方动作语义

以下为 CC4 官方文档的释义。持续时间按官方默认配置；实施时必须核验实际使用的 CC4 版本与环境配置，不得复制教程中为演示而把 duration 改为1的代码。[S1]

| 项目内ID | 论文名称 | 序列规范值 | CC4 对应动作 | 默认持续时间 |
|---:|---|---|---|---:|
| 0 | no-op | no_op | Sleep | 1 tick |
| 1 | analyse | analyse | Analyse | 2 ticks |
| 2 | remove | remove | Remove | 3 ticks |
| 3 | restore | restore | Restore | 5 ticks |

上述0—3是项目自己的高层动作编码，不是所有 CC4 wrapper 中的全局动作索引；底层参数化动作空间可能包含不同主机目标。

#### 1.2.1 no_op / Sleep

**官方事实：**Sleep 表示当前回合不主动影响环境，不需要目标主机参数。它不终止环境运行。Monitor 默认在每步末自动运行，收集网络连接和进程创建事件，所以 Sleep 不等于停止所有告警观测，但也不等于执行主机文件调查。[S2][S3]

**规划说明：**没有必要进行主动处置时，等待可以避免额外响应；但 Sleep 不清除攻击会话、不重置主机，持续等待也可能放任攻击损失累积。不要将“未主动操作”解释为“必然没有业务损失”。

#### 1.2.2 analyse / Analyse

**官方事实：**Analyse 对指定主机收集与恶意软件相关的进一步信息，官方示例包括文件名称、路径等文件证据。它是调查，不是清除。成功执行时也可能没有新增观测。[S4]

**规划说明：**在新的调查信息可能改变后续处置时考虑 Analyse；不要把 Analyse 设成所有响应的强制前置步骤。动作执行成功、发现证据、清除攻击是三个不同事件。无新增证据不自动等于主机干净。

#### 1.2.3 remove / Remove

**官方事实：**Remove 尝试清除用户级攻击会话，不能替代 Restore 清除 root 级会话。官方教程展示：针对仅有 root 会话的主机执行 Remove，蓝方可能仍收到成功反馈，但 root 会话没有被移除。[S5]

**规划说明：**不能把 Remove 描述为无条件清除所有恶意活动的通用修复；多次执行也不保证可以处理高权限失陷。不得仅凭 success=True 判断主机已经恢复。证据不足可以降低计划评分，但不是删除合法 Remove 首动作的理由。

#### 1.2.4 restore / Restore

**官方事实：**Restore 对主机重镜像，恢复到已知良好状态，清除恶意活动，包括教程展示的 root 级攻击会话，并恢复红方修改的文件。该动作影响主机可用性，恢复期间可能导致正常业务工作失败。[S1][S6]

**规划说明：**必须同时描述它的能力与代价，不能只强调“耗时最长”。权衡恢复期间损失和继续失陷的损失；严重或持续失陷时，立即 Restore 必须保留为合法候选。成功恢复不应被当作此后永久不会再次感染，也不应无依据反复恢复。

#### 1.2.5 公共时间与执行规则

1. tick 是全局仿真时间步，不是秒；计划长度4表示4次顺序响应决策，不是连续4个tick各发起一次动作。
2. 同一智能体执行中的动作完成前，不发起新的响应；官方动作不可取消。[S1]
3. 忙碌期间继续接收并按真实到达时间记录合法观测，但不重复发起 LLM/PPO 决策。
4. 真实执行仍只提交计划首动作；后续三步是预测方案，不是已经承诺执行的动作。
5. 统一目标解析器负责指定主机；LLM 不额外创造目标主机，不增加隐含动作参数。当前合法性、目标解析和底层提交必须使用同一个已冻结规则。
6. 请求动作、映射后动作、目标主机、执行完成与处置效果分开记录。不能把被转换成Sleep的请求仍统计成成功执行Restore。

### 1.3 首动作分组与覆盖约束

设当前真正可以发起新决策的时刻为 t，A_t 为公共接口确定的合法高层动作集合。对每个 a ∈ A_t，必须有且仅有两条有效候选，其首动作为 a，完整动作序列互不相同。

```text
count(valid plans with first_action=a) = 2, for every a in A_t
N_valid = 2 * |A_t|   # 非单一强制动作特例
```

当四类动作全部合法时，总计8条。固定槽位分组可为0—1/no_op、2—3/analyse、4—5/remove、6—7/restore，但槽位只是存储方式，不携带价值排序语义。

**合法性不等于收益判断。**主机未被证明失陷、风险评分低、动作成本高、LLM先验低或WM预测不确定，均不能自动成为屏蔽首动作的理由。只有公共执行接口在当前合法观测与已知约束下无法构造可执行动作时，才屏蔽该动作组。不得读取真实攻击会话或隐藏失陷状态构造动作掩码。

### 1.4 LLM 生成任务

不再要求“自由生成8个最佳计划”，改为：

> 对每个当前合法首动作，分别生成两条四步计划。第一步必须是指定动作；后续三步根据已提供的事件信息和官方动作机制安排。两条计划须有不同且可解释的后续序列。所有计划按照同一任务目标给出先验偏好，不要把先验分数当作合法性判断。

采用一次结构化请求生成所有有效组，而不是每组分别调用一次。每条计划给出 actions、原始先验评分、简短依据；依据只用于审计，不作为硬编码执行规则。

后续序列的差异不强制“一条保守、一条激进”，不通过无必要重复Restore、随机替换动作或只改理由来凑数。不能要求每组必有相同最高分；组间偏好需要可比较，不在每组内单独归一化后抹去组间差异。

本步骤确定先验不得参与硬删除；具体分数校准和策略融合方式在后续步骤单独确定。

### 1.5 校验与确定性修复

处理顺序固定为：

```text
输入可见状态和公共合法动作掩码
→ 一次生成
→ 解析结构化输出
→ 按真实首动作归组
→ 校验动作枚举、长度、评分有限性
→ 按完整动作序列去重
→ 每个合法动作组保留两条
→ 不足的组确定性补齐
→ 屏蔽非法组及填充槽位
→ 验证覆盖不变量
→ 输出候选、先验、掩码及审计元数据
```

**不得做跨组全局Top-N筛选。**某组候选多时，只在该组内部选择；不能挤掉其他组。错组候选按其实际首动作归属处理，不能只改首动作字段并继续沿用原理由、原评分。

**备用补齐：**只修复缺失槽位，不覆盖全部正常LLM计划。令a为待补齐组的首动作、0为no_op，按以下固定顺序扫描备用池，跳过该组已存在的完整序列，补至两条后停止：

```text
(a, 0, 0, 0)
(a, 1, 0, 0)
(a, 2, 0, 0)
(a, 3, 0, 0)
```

这个备用池优先使用“首动作后暂缓干预”与“首动作后调查”的简单后续安排，不表示这些后续方案最优；其职责是提供不同序列并保护首动作覆盖。未来动作是否合法仍遵循1.6节，不能查询真实未来。备用池应版本化，所有变体和split采用同一规则。仅Sleep合法的强制动作特例不进入此补齐流程。

**来源与评分：**每条候选记录 source=llm 或 deterministic_fallback。备用计划的 raw_prior_score=null、prior_score_present=false，不伪造LLM原始评分。为兼容有限数值输入，score_input取本次有效LLM候选原始评分的均值；完全没有有效LLM评分时统一取0.5。正常LLM候选的score_input等于其原始评分。这个填充值是缺失值的中性工程处理，不是LLM置信度或真实回报。后续先验校准可以版本化修订，但不得隐式改变来源。先验为零、未知或较低，不允许自动生成 -inf 动作掩码。

**失败处理：**LLM超时、JSON错误或重复输出时采用相同确定性补齐路径，不无限重试，不在正式测试时临时人工修改候选。若校验后仍无法满足公共合法覆盖条件，记录接口错误；开发验收不通过，不以静默Sleep替代并宣称修复成功。

### 1.6 特殊情况

| 情形 | 处理 |
|---|---|
| 四类动作均合法 | 每组2条，共8条 |
| 只有部分动作合法 | 合法组各2条；非法组屏蔽，不转成额外Sleep计划 |
| 仅Sleep合法 | 绕过LLM与候选选择，执行公共强制Sleep路径；其时间和环境奖励仍计入轨迹，不把它当作可学习的自由选择 |
| 当前动作尚未完成 | 不发起新决策；环境推进与观测记录继续 |
| 同组仅1条或有重复 | 仅补该组缺失槽位，记录原因及来源 |
| episode结束 | 不生成新候选，不创造终止后的决策 |
| 未来步骤可能不合法 | 不根据真实未来筛选；也不把当前首动作掩码机械套到未来全部步骤，交由后续统一预测/执行语义处理 |

固定形状可使用8×4动作数组和长度8的candidate_mask。填充值不具备动作语义，不参与先验归一化、策略softmax、熵计算、critic池化或WM有效候选统计。LLM候选、先验、WM特征和mask始终按稳定candidate_id对齐。

### 1.7 复盘后补充的工程边界

**边界一：缓存必须失效分代。**新N=8与旧N=6不能共用缓存身份。键和manifest至少包含动作契约版本、提示词版本、候选规则版本、N、H、模型准确标识、生成配置、合法性/目标解析器版本及输入摘要标识。若后续加入历史文本，缓存键必须同步包含历史摘要内容，不能仍只用D27。

**边界二：离线处理也须保持覆盖。**旧缓存迁移、检索缓存返回、去重、合法性过滤和真实动作提交前都检查覆盖；只在原始LLM输出检查一次不够。训练和评估使用同样的规则。

**边界三：通用接口去掉硬编码6。**解析、PriorBatch、特征形状、buffer、actor/critic、rollout、cache、日志和测试都检查N与H的配置一致性。旧checkpoint是否兼容由模型与预处理契约判定，不默认可直接继续训练，也不默认所有权重都必须丢弃。

**边界四：配额不应成为新价值偏置。**组数均衡只消除数量差异，不强制最终动作均匀。固定顺序不得形成候选索引捷径；后续网络需验证候选与特征同步置换时行为保持一致。具体后验结构仍待讨论。

**边界五：同目标、同合法性。**当前主机目标由共同解析器决定，不能让完整模型比消融额外获取目标真值或更有利的目标解析路径。候选首动作与实际提交不一致必须单独报警、统计。

**边界六：补齐属于接口保护，不冒充LLM收益。**分别报告LLM原始覆盖、修复后覆盖、备用占比。仅靠备用计划改善不能证明LLM语义先验有效。

**边界七：训练真值与执行观测分离。**最终文稿允许仿真训练奖励及评价依赖其定义中的失陷事件；这些标签只进入奖励/评测数据通道，不因此获得进入LLM输入、在线目标解析或动作掩码的权限。[P1]

### 1.8 观测与审计指标

至少记录并区分：

| 指标 | 用途 |
|---|---|
| per_action_legal_decisions | 每类动作在有效决策点合法的次数 |
| raw_llm_first_action_coverage | 补齐前LLM本身的首动作覆盖能力 |
| final_first_action_coverage | 进入策略前的最终覆盖能力；合法动作必须为100% |
| valid_candidate_count_by_first_action | 每组有效候选数；非强制动作情形每组恰好2 |
| duplicate_rate / schema_failure_rate | 是否依赖重复计划或解析修复 |
| fallback_rate_by_action / reason | 各动作的补齐来源与原因 |
| requested_action_count / executed_action_count | 区分请求与真正执行，避免映射后统计失真 |
| selected_fallback_rate | 最终策略是否主要依赖备用计划 |
| provider_calls / cache_hits / latency | 调用成本、缓存收益和实际时延 |

这些指标是接口诊断，不替代最终论文评价指标，也不参与测试集上的临时调参。

### 1.9 消融一致性

LLM-RL和LWM-RL采用完全相同的官方动作说明、分组生成、去重、补齐与掩码规则。在相同输入及缓存身份下，二者获得相同的LLM候选；它们沿各自真实轨迹访问不同状态时，汇总候选分布可以不同。

WM-RL的非LLM候选构造需匹配合法首动作覆盖和候选预算，不得继续使用LLM计划却称为无LLM。其具体生成策略后续确定。RL-Only共享合法性、目标解析和环境时间语义，但不为凑候选数强行改成冗余八动作基线。

- [ ] LLM-RL和LWM-RL在相同输入上候选完全一致；公共接口不读取隐藏失陷真值。
- [ ] 分别输出原始LLM覆盖、补齐覆盖、备用率和请求/实际执行差异。

### 1.11 本步骤不能证明的事项

## 2. STEP-02：同源事件信息与可观测响应记忆

### 2.1 确认范围与目标

**确认状态：用户已确认；设计生效，尚未实施和验收。**本步把0917文稿中的事件信息“文本描述与向量表示”落实为可核验的同源输入，而不是恢复旧论文的全部特征选择流程。[P1][D2]

保持D27基础字段的含义和次序，追加目标绑定的可见证据与自身响应记忆：

```text
v_t = concat(D27_t, visible_evidence_t, response_memory_t)
c_t = deterministic_template(same_source_record_t)
```

c_t与v_t使用同一时刻、同一允许信息源。JSON形式的D27数值不是新增事件上下文的替代品。准确新增字段和总维度须在核对实际Blue观测接口后固定；本步不凭空设定D40/D64，也不默认旧D27模型可直接使用扩展输入。

本步修复的是“策略不知道对同一主机已经做过什么、证据是否有实际变化”的输入缺口。STEP-01的A4、N8/H4、合法首动作等配额保持生效；奖励权重、PPO后验结构、WM预测目标与训练预算本步不更改。

### 2.2 统一输入记录与来源边界

| 信息块 | 确认纳入的事实 | 来源和边界 |
|---|---|---|
| 基础状态 | 当前D27字段 | 保留原定义，不改变旧字段语义 |
| 当前响应目标 | Analyse/Remove/Restore各自经公共解析器确定的目标、合法性、可见区域信息 | 解析当前快照，不能读取隐藏攻击真值，不能修改环境 |
| 可见证据 | 实际返回的进程、网络连接、文件证据，以及可见的文件名、路径等语义字段 | 仅来自该智能体在当时已收到的合法Blue观测 |
| 时间与变化 | 首次/最近观测时间、新出现或重复出现、处置前后观测变化 | 使用可观察到达时间；不能用未来日志回填过去输入 |
| 响应记忆 | 实际执行过的动作、目标、开始/完成时间、可见执行结果 | 记录自身行动事实，区分request、execution、completion与eradication |
| 缺失与截断 | 未调查、字段未返回、无新增结果、历史省略情况 | 未知不能填成“正常/干净/已恢复” |

只允许当前及历史的合法蓝方观测、自身实际响应记录与公开环境/动作契约。没有本轮新增的跨智能体消息协议，不得把其他Blue的私有观测或未来动作直接加入本智能体状态。

禁止把真实Red session、控制器compromise flag、真实失陷开始时间、仿真内部攻击者身份、未来奖励或评估标签作为事件输入。训练奖励/监督标签通道与policy observation隔离；某个字段用于训练标签不意味着它可以进入输入。

允许记录公开动作机制，例如Remove不能替代Restore清除root会话[S5]；但不能因可疑观测而直接生成“当前主机确定为root失陷”的事实标签。

### 2.3 目标绑定与实体一致性

先在当前决策快照上通过公共解析器获得三个非Sleep动作对应的目标，再构造目标摘要。三个动作指向同一主机时合并为一份；指向不同主机时分别保留。最多3台当前动作目标，不另选任意“top-3”替代，不为凑数量添加主机，也不因文本长度限制遗漏实际目标。

保留动作到目标的映射及缺失/非法标记。Sleep不伪造目标主机。LLM仍生成高层动作类型序列，不获得选择额外主机的权限；后续三个动作的目标只在未来预测/实际决策时按统一规则解析，不被当前摘要永久绑定。

响应记忆按episode、agent与稳定可见主机身份绑定，不按会变化的排名槽位绑定。当前目标切换后，不得把上一台主机的处置历史移到新目标。内部可为已观测主机保留必要历史，以便其再次成为目标时恢复正确摘要；只将当前相关目标的摘要提交给LLM。

### 2.4 已确认的初始配置

| 参数 | 确认值 | 解释 |
|---|---|---|
| recent_event_window_ticks | 50 | 最近50个全局环境tick内已到达的观测，不是50次策略决策 |
| current_target_hosts_max | 3 | 由三个非Sleep动作目标去重得到，不是风险排名固定选3台 |
| completed_response_records_per_host | 4 | 每台目标最近4次已完成响应的详细记录 |
| persistent_action_summary | Analyse/Remove/Restore各自最近一次完成时间与结果 | 可超出50tick窗口，但不跨episode |
| text_builder | 确定性模板 | 不增加另一个LLM摘要调用 |
| decision_update | 每次真正可发起新响应时 | 不改为每50tick才决策 |
| episode_reset | 清空动态证据与响应记忆 | 禁止跨episode或跨split携带环境动态状态 |

50tick和4条记录是已确认的初始工程配置，不是论文已有的最优常数，也不是性能最优性证据。之后如需调整，须记录新版本与基于训练/验证的理由。

窗口边界按已完成且已提供给智能体的全局tick定义。实现时固定同tick内“接收观测—更新记忆—构造输入—发起动作”的先后次序；任何完成结果只有到达后才可影响下一输入。

### 2.5 证据变化、去重和缺失状态

证据记录至少能够区分首次观测、重复返回的既有证据和响应完成后首次观测到的证据。按照实际可见实体、事件内容和可用时间/标识区分，不能将同一文件条目每次返回都计为新攻击，也不能把确实发生于不同时间的同类连接一律合并成同一事件。

“动作后首次观测到”不等于“该动作后才真正产生”，更不等于“由该动作导致”。没有可靠源事件时间时，只陈述首次观测时间。不能把处置后新告警直接等同于处置失败或高权限失陷。

以下状态分别编码并在文本中明确：unknown、not_observed、observed_absent（仅在接口确实支持明确否定观察时使用）、no_new_observation。零值或空数组不能同时代表这些不同含义。

Analyse成功但无新增返回，不代表已确认主机干净[S4]；没有重新返回旧证据，也不代表旧问题已消失。历史超出50tick只改变“是否近期”，不凭空宣布证据失效或风险已清除。

### 2.6 响应历史和持久摘要

详细记录包括请求动作、实际动作、目标、真实开始时间、完成时间、可见结果及完成后新观测的摘要。被拒绝或映射成Sleep的Remove请求不能记作成功完成Remove；失败尝试应在审计中保留，但不能伪装成完成的处置。

最近4次已完成响应之外，保留各目标最近一次Analyse、Remove、Restore的完成时间与可见结果。执行中的动作单独标记，不提前填写未来完成时间/结果作为已知事实。Sleep是无主机目标行为，不为了充满主机历史而复制进各主机。

Remove的success不能作为彻底清除的证明[S5]。Restore完成时的事实不等于永久安全；后续仍要根据实际到达的新观测更新摘要[S6]。不手工写“连续两次Remove后必须Restore”或“Analyse两次以后禁止Analyse”之类新响应规则。

当详细历史被截断时，同时记录历史存在更早条目/省略数量等可获得标记；不得让文本误导为整个episode只发生过这4次操作。长动作执行中继续接收合法观测并更新证据账本，但不重复调用LLM或创建新自主动作。

### 2.7 同源文本与数值表示

采用一个统一事实记录生成两个视图，而不是分别从不同数据库或不同时间片制作：

```text
合法Blue观测 + 自身实际动作记录
              ↓
带来源、时间、目标及缺失标记的事件记录
              ↓
扩展数值向量v_t + 模板文本c_t
```

模板优先说明当前目标、实际证据、变化和已完成响应。可以附公开动作语义提醒；不能插入未验证攻击阶段、隐藏失陷概率、未来损失或固定“正确动作”。假想案例仅用于文档解释，不能混入真实训练样本。

文件路径、命令片段、日志描述等自由文本只作为证据数据，转义和限定边界，不作为系统指令执行。不直接序列化整个仿真对象。摘要由程序完成，不另增LLM总结步骤；一次候选生成请求可以读取全部当前有效目标摘要。

确切语义字段编码、词表/特征数及长度预算待观测接口核验后确定。编码可以不同，但文本中用于推理的事实必须能由对应的同源记录和数值/语义表示追溯；不能宣称数值分支含有某字段而实际丢弃其内容。

### 2.8 消融的信息公平

LLM-RL与LWM-RL使用相同的事实摘要、提示词和缓存规则。RL-Only与WM-RL也获得相应数值化证据与响应记忆；不能只给完整模型处置历史，再把增益全部解释为LLM/WM模块贡献。

公平的是信息可用范围，不要求不同模型采取完全相同的编码结构。若文字含文件/连接语义，非LLM分支不能仅拿一个有无标记却被称为完全同信息；字段编码表必须明确其语义保留方式和不可逆压缩范围。

主Table 2中各变体共享本步的输入构造协议和可见性边界。旧D27-only模型可保留为历史/额外诊断，但不与新输入的完整模型混作严格组件消融。

### 2.9 缓存与旧产物迁移

缓存身份至少涵盖基础状态、目标证据摘要、响应记忆、当前合法动作与目标映射、事件摘要版本、提示词与模型版本，以及STEP-01候选协议身份。

不能D27相近就忽略处置历史差异继续复用相同先验，尤其不能把“从未处置”与“刚做过Remove且有新证据”合并为未区分的状态。若采用近邻检索，允许的近似及拒绝策略另行版本化确认；本步不默认新增字段后旧D27检索仍然有效。

已有replay若保存了完整合法观测和动作时间记录，可因果重放构造新输入；若缺少字段，不能从未来、隐藏真值或随意补零还原历史。必要时重新采集训练/验证数据，并建立新的输入与实验lineage。旧D27权重是否可迁移需明确适配和验证，不默认为兼容。

本次仅修订设计，不启动重训、不修改旧repeat1、不把新输入模型与旧缓存拼接发布。原始DOCX保持不变；随后论文定稿时应明确补充本步工程定义及其来源。

## 3. STEP-03：响应间隔一致的状态—双损失集成WM

### 3.1 确认结论与复杂度边界

**用户已确认，尚未实施和验收。**用户同时要求避免复杂设计，以实际结果为优先。本步保留上一轮建议中的必要部分：5个独立概率模型成员、真实响应间隔转移、已知字段规则更新、恢复延迟/业务失败双损失预测。[D3]

采用小型MLP实现，每个成员内部可以共用骨干，输出动态状态、延迟损失和业务失败损失；成员之间参数独立。不为此增加Transformer、GNN、额外攻击分类器或新的LLM调用。网络具体宽度等沿用可复用配置，必要调整依据训练/验证，不在此堆叠搜索空间。

N=8、H=4、原生A4、STEP-02同源输入及0917奖励目标不变。双损失头是预测既有奖励的两个分量，不是新增奖励；不增加Analyse取证奖励、Restore完成奖励或旧版提前预警奖励。[P1]

本步保证的是实现契约可验证，不承诺模型必然提高最终性能。未通过一致性/预测验证的版本停留在开发阶段；所有负结果保留，不能通过筛选测试种子或削弱消融获得预定排序。

### 3.2 模型输入与三个输出部分

输入为当前可见事件向量v_t、当时已确定的动作类型，以及公共解析器得到的可见目标信息。v_t包含STEP-02的D27基础、目标证据和响应记忆。不得输入未来动作结果、真实失陷标志、真实失陷起点或真实Red会话。

| 输出部分 | 训练对象 | 作用 |
|---|---|---|
| 动态状态预测 | 下一可决策时刻的不确定可观测结果与动态特征 | 支持后续候选计划递推 |
| 延迟损失预测 | 当前响应间隔内，按0917奖励定义计算的延迟惩罚量 | 区分继续拖延与有效处置 |
| 业务失败损失预测 | 同一间隔内，按统一范围统计的Host Work Fail惩罚量 | 学习处置扰动与持续失陷的业务影响 |

真实失陷信息仅可用于环境外部奖励/监督标签通道，不因为要预测该损失而成为模型输入。模型学习的是从允许信息估计损失，不能把预测结果描述为已获知真实失陷状态。

训练时不得以事后得知的完成结果或事后映射作为决策前已知输入。提交前即可确定的合法性映射使用统一规则；提交后才发生的拒绝、结果变化作为结果记录/标签，保留requested、submitted、executed差异。

### 3.3 转移时间单位与记账

一个样本覆盖“当前有效响应开始前 → 该响应结束后的下一可决策时刻”，而不是一律只跨1tick。实际间隔记为dt；默认动作时长由STEP-01的锁定环境契约提供，异常、回退或episode截断时使用真实记录。

```text
(v_t, 当时可知的动作/目标, dt,
 v_next, interval_delay_loss, interval_failure_loss,
 episode_end, truncation, outcome_masks)
```

dt是实际持续时间标签/记录；预测时仅使用当时已知的持续时间规则和剩余episode时间，不读取未来的实际完成日志。完整的逐tick原始损失同时保留，便于重建和审计。

若采用全局tick折扣，令d、f为既有奖励定义中的非负损失量：

```text
D_t = sum(gamma_tick**l * d[t+l], l=0..dt-1)
F_t = sum(gamma_tick**l * f[t+l], l=0..dt-1)
R_t = -lambda_delay * D_t - lambda_failure * F_t
```

WM分别预测D_t、F_t，再按同一配置合成R_t。计划中下一响应的外层折扣按此前累计dt计算，不能只折扣动作编号，也不能把间隔内部再次折扣。PPO训练记账随后必须与这一目标一致；若旧代码采用未折扣间隔和，必须显式版本化修正，不静默混用旧标签。

官方评价仍按冻结的episode/tick指标统计，不把训练折扣强行应用到最终表格。所统计的主机范围、团队/局部奖励归属、符号及权重必须与真实训练奖励一致，不能只预测当前目标的失败，却把它当作全域失败。

动作被拒绝、映射为Sleep、只剩部分episode时间或环境终止时，保留真实持续时间和结果；不虚构完整执行成功，不构造episode结束之后的下一状态。强制等待和忙碌期间的奖励不得漏记。

### 3.4 已知部分规则更新，不确定部分由模型学习

已知身份和动作类型、可确定的时间推进、历史队列移位等由程序更新；是否成功、实际新增证据和损失由模型预测或按真实标签学习。

```text
当前状态/记忆 + 动作/目标
       ↓
预测不确定的结果与两类损失
       ↓
按已知动作和时间规则更新记忆
       ↓
组装下一事件向量
```

不能因为选择Restore就强制写“已成功、永久干净、未来零损失”。字段只有在输入和已知规则足以确定时才能绕开模型。50tick窗口计数等若还依赖未保留的事件年龄，不能凭汇总数声称可精确更新；应保留必要队列信息，或将该动态量明确交给模型预测。未知字段有mask，不伪装为零或正常。

连续动态量采用合适的数值分布输出；动作执行结果等类别字段采用类别输出，不把所有字段一律当作无约束高斯数。确切字段类型跟随STEP-02的实际接口清单锁定。WM不生成文本，也不访问真实未来日志重新构造预测状态。

在同状态、同目标、同当前动作下，第一步预测分布不依赖候选计划的后续三个动作。同首动作的两条候选先共享相同的条件转移含义，再从后续不同动作分叉；若随机采样，比较的是分布，不要求独立抽样数值相同。

### 3.5 5成员集成与不确定性

每个成员独立初始化，并在训练episode层面进行独立重采样；同一成员内可共享状态与两类损失的编码骨干。不把一个已训练模型复制5次冒充集成，也不让全部成员共用一个未集成的奖励预测器后声称已覆盖奖励模型分歧。

保留状态预测分歧，以及延迟/失败/合成回报的成员分歧，作为不同的诊断量。状态分歧仅在相关、有效且量纲可比较的动态字段上计算；固定身份字段不用于稀释误差。

成员分歧只能反映成员之间的不一致，不能覆盖全部共同偏差；模型输出的分布方差与成员分歧也不能混称。不得仅凭低分歧宣称预测正确，或因高分歧把合法Restore从候选池删除。

沿计划多步传播的方式、候选级u_i最终定义、归一化与PPO使用方式留待STEP-04及后续对应步骤确定；本步不将不同量纲的不确定性随意相加。

### 3.6 数据覆盖、旧数据复用与公平

检查四类实际动作及其主要可见上下文的样本覆盖，特别是首次响应、Analyse之后、Remove之后再出现新观测、Restore期间及其完成后的记录。覆盖检查用于补充训练数据，不是新增固定响应规则。

仅从训练环境补采；验证用于模型选择和误差核验，测试不参与补采策略设计。保留完整episode划分，避免相邻转移跨训练/验证泄漏；记录其他智能体采集策略版本，不读取其未来动作作为本策略输入。

旧replay包含完整合法观测、逐tick奖励分量和动作时间时，可因果重构并复用；缺失历史或分项标签时不能靠未来真值、零填充或比例拆分编造数据。新模型建立新输入/奖励/数据manifest，旧D27权重仅可在明确适配并验证后迁移。

WM-RL与LWM-RL使用同一WM接口与同等数据/训练条件；不能只为完整方法提供更强奖励模型。奖励消融时，rollout合成目标也必须与该变体的真实训练目标相同。正式比较的具体复用和预算计数后续统一确定，不以本步授权额外隐性训练预算。

### 3.7 最小验收与实施完成度

本次只确认设计，以下项目尚未运行：

- [ ] 逐tick奖励与响应间隔奖励重组一致，符号、权重、统计主机范围和终止处理一致。
- [ ] 输入没有未来完成结果和隐藏真值；固定更新字段与动态预测字段边界明确。
- [ ] 同状态/目标/首动作的第一步预测分布一致，不受候选尾部或槽位编号影响。
- [ ] 按Sleep、Analyse、Remove、Restore分别报告动态状态误差和两类损失误差、偏差及样本数。
- [ ] 与状态保持不变、训练集简单损失均值等基线比较，避免总体RMSE掩盖关键动作问题。
- [ ] 检查成员分歧与误差的关系，不把一致但错误的模型判为已校准。
- [ ] episode划分、旧新数据和模型版本可追溯，缺失样本不伪造为覆盖完整。

没有同状态反事实分支时，普通日志仅验证实际执行动作的预测，不能拿未执行动作的虚构结果计算真实排序regret。仅预测误差改善也不足以证明最终PPO增益，真实验证对照仍需保留。
